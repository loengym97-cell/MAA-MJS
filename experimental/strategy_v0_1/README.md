# 千里走单骑「策略by兔兔」（v1.4.0 正式版）

本策略自项目 v1.4.0 起与原策略共存。原「官服」资源仍运行旧策略；选择「官服·策略by兔兔」时，先加载原有 `resource`，再加载本目录的策略节点与覆盖。正式 pipeline 保持原样。

## 在 MAA 图形界面里运行

打开仓库根目录的 `MFAAvalonia.exe`，在资源选择中选「官服·策略by兔兔」，再勾选「千里走单骑【策略by兔兔】从主页开局」或「千里走单骑【策略by兔兔】地图续打」。不要同时勾选旧策略入口。想用旧策略时把资源切回「官服」。本目录下的旧 `gui/` 是本地试跑副本，不随 GitHub 源码发布。

选择「安卓端」。只有已经在选关地图时才使用“地图续打”；续打无法自动得知此前已有的信物，可能再次尝试购买，因此更建议从主页新开一局。若任务列表没有刷新，关闭界面后重新启动。

图形界面目前固定为默认策略：商店只买 3/4 分信物与行囊、单店最多 9 件高分信物，不买武将牌。下文的 `--min-shop-score`、`--max-relic-per-shop`、`--owned-relics` 是命令行入口的参数，不会被图形界面继承。首次实机运行请在旁边观察，遇到错误及时停止。

## 现在的选择规则

- 通关赠礼页：读取三个“某某赠礼”，按策略 PDF 的高分档给人排序。点进最优人选后，再看实际提供的是“信物”还是“驰援”。高分且未持有的信物与高分驰援优先；没有高分选项时，优先选不占信物格子的驰援或资助。不会把“萧何赠礼”误存成武将名“萧何”的另一种名字。
- 赠礼转场与漏点：点击后等待 1 秒。若确认仍在原赠礼页，选人或选礼最多尝试 10 次；黑屏或无法确认当前页面时不盲点。只有识别到下一页后才记录信物已获得。
- 巴清、吕不韦商店：从原 Excel 的“武将→信物”两列建立名称映射，另补入用户指定的新版信物；商店按信物实际名称识别。只考虑 3/4 分信物；先买这些信物，再买行囊。价格和余额每次从屏幕读取，绝不写死 30。武将牌暂时不买。
- 商店入口：首次点商人后验证是否进店。若仍在地图且商人头像还能识别，最多补点 10 次；已经进店或画面不确定时不会重复点击。
- 多商品商店：按高分信物顺序逐件处理；每笔完成或跳过后重新截图、重新识别剩余商品和余额，再选下一件。高分信物处理完才考虑行囊，武将牌不买。
- 行囊：每次商店出现且余额足够就买一次；跨商店没有总次数上限。游戏画面中的单店“限购 1”仍然有效。
- 每次购买前检查弹窗商品名称、左侧购买按钮、价格及余额。商品弹窗、取消弹窗、退出商店若确认未生效，最多尝试 10 次；付款仅在同一弹窗与原余额持续可验证时重试，任何扣款不明都停止重复付款。无法识别当前页面时安全停止。
- 新增可选 3 分信物：张春华、司马懿、孙策；新增可选 3 分驰援：曹丕、周勃、虞姬。原有 4 分优先级不降低。
- 弃牌流 4 分信物：龙且—将印、章邯—衔枚、子婴—传国玺。将印的对应关系见旧 Excel；章邯/子婴是用户提供的新版暂定映射，旧 Excel 尚无这两行，后续以实机显示核对。

## 命令行使用

在仓库根目录运行：

```powershell
.\python\python.exe experimental\strategy_v0_1\千里策略试验版.py
```

上面只打印策略计划，不连接游戏。确认无误后，关闭正在控制同一模拟器的正式任务，再运行：

```powershell
.\python\python.exe experimental\strategy_v0_1\千里策略试验版.py --run --entry start
```

`--entry start`（默认）从千里主页开新局。已经在选关地图中续打时改用 `--entry continue`，最好再填 `--owned-relics "吕布,萧何"`，让脚本知道这一局已有的信物；否则它无法从现有画面推断之前获得了什么。如果发现多台安卓设备，增加 `--device 127.0.0.1:端口`。可用 `--min-shop-score 4` 收紧购买范围；默认 3 分以上。默认单店最多买 9 个高分信物，等于允许把遇到的高分信物都买下；要更省钱可用 `--max-relic-per-shop 1`。

离线检查资源和 Agent 连接，不操作游戏：

```powershell
.\python\python.exe experimental\strategy_v0_1\千里策略试验版.py --check-agent
```

发布包内置运行必需的高分信物名称映射；仓库根目录的《西楚版本无尽千里全赠礼全事件.xlsx》为可选的完整资料，不随 GitHub 源码发布。仍需项目自带的 MaaFramework Python 及 OCR 模型。本策略从 v1.4.0 起正式提供，首次使用建议观察赠礼和两种商店的日志；原有事件识别和战斗兜底仍沿用原资源。本策略取消层数上限，可无限续打。目录名与脚本文件名保留「试验版」仅为兼容既有入口。
